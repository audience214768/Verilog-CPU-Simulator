### 1.1 两棵现行树：提交 T1a（W3） / 工作区 dual2（W2）

- **C** = 双发射、宽窗口的乱序核 ＋ 三把刀短路 ＋ I/D cache 定型配置。
- **三把刀** = load 交付链上的三级流水寄存器改组合直连：刀 R（`mem_subsystem.v` 的 `dl_*_r`）、
  刀 D/Q（`cpu_top.v` 的 `ld_done_*_q`）、刀 A（`cpu_top.v` 的 load CDB 组）。
  短路后各级**必须保持的不变式**（`ld_busy` 必须组合兑现 / SQ 快照与退休的 2 拍裕量 /
  `lsq_invalidate` 必须留打拍）写在两处 RTL 头注释里，**再插同类寄存器前先读那里**。
- **T1a**（2026-10-15）= 三发射 ＋ I-cache 扩容（已提交）；工作区把 `ISSUE_WIDTH` 切回 2 即 **dual2**。
  参数事实见 `architecture.md` §2；工作区当前值另见 `student_top.v` 的 parameter 声明。

|---|---:|---:|---:|---:|---:|---:|---:|
| 提交 C＋T1a（W3） | 0.7624 | 1.1208 | 0.6959 | 0.8127 | 0.6105 | 0.8614 | **0.7959** |

## 2. 下阶段任务计划

### 方针（2026-10-01 用户裁定）

> **核心思路 = 提升 IPC 最小的那些程序**；针对"该程序的算法结构 + 它的气泡现状"做定向优化。

判分是 6 个 `perf_*` 的几何平均 ⇒ 相对增益上六程序等价；理由不是权重而是**绝对余量**：
现行树最低三个是 `towers 0.6105 / qsort 0.6959 / median 0.7624`，而 `multiply 1.1208` 已贴算法上界。
（六例逐点变化见 `docs/timing/results.csv` 的 `ipc6` 列。）

**四个步骤，顺序不可颠倒**：

1. 读 `testcases/perf_*/program.S` 定出算法结构：并发地址流条数、复用距离、store:load 比 σ；
2. 用探针定出该程序的气泡归因 —— 到底谁在阻塞（访存延迟 / AR 带宽 / 失效 churn / 前端 / 依赖链）；
3. 用**由算法推出的判据**选方向（`h/m > L`、`a ≈ 相联度/σ`、地址别名关系）；
4. 预注册方向性预测再测；增益落点必须与机制预测逐例对上（对不上就是机制没搞对）。

**逐程序画像**（步骤 1 的产出；结构性量，与参数无关）：

| 程序 | 算法 | 并发流 | σ = store/load | `a`（访问/填充） | `a/L` | 结构性气泡 |
|---|---|---|---|---|---|---|
| towers | 链表汉诺塔（`list_push/pop`），足迹 ~360 B ≈ 12 行 | 节点链 + 栈 | **0.84** | 2.48 | **0.31** | 失效 churn（`clr/vset = 9.3×`）；对容量/相联度免疫 |
| qsort | Hoare 划分 + 插入排序叶子（`n≤10`） | 划分双指针 + 校验双流 | 0.37 | 2.72 | **0.34** | 划分循环 load:store = 1:1 且写回刚读的地址；校验双流差 0x2000 同组 |
| rsort | LSD 基数排序，1 KB 计数表 × 32 组恰好 1 行/组 | 计数表 + input + scratch + 校验双流 | 0.76 | 1.90 | **0.24** | 失效 churn（18.5×）；RR 交替驱逐热计数表 |
| median | 顺序扫描 | 1~2 | 0.20 | 13.26 | 1.66 | 已过 `h/m > L` 线，余量小 |
| multiply | 乘加循环，每 81 拍才 1 条 load | 1 | 0.14 | 7.54 | 0.94 | 不是访存程序，缓存对它天然无用 |
| vvadd | 纯顺序向量加 | 3 | 0.25 | 7.89 | 0.99 | 带宽打平，收益全在延迟 |

**反面清单**：不为抬高几何平均去做**只对健康程序有效**的改动；不做**与算法结构对不上**的通用调优；
参数不作为默认方向（§0 口径：用户指定时才扫，且必须综合定价）。

### 验证纪律：TB 分三类，各配不同寿命（2026-10-13 用户裁定）

分界线不在"长命 vs 一次性"，而在**判据挂在协议上还是挂在拍数上**：

| 类 | 判据来源 | 寿命 | 例 |
|---|---|---|---|
| **契约** | 接口承诺（只依赖"设计对外保证什么"） | **永不过期，值得养** | `ld_busy==0` 必须当场兑现；每个被接受的 load 恰好回一个 `ld_done_valid`；已提交 store 留到 B 握手且之前的 load 都回；AXI4-Lite 合法性 |
| **机制** | 这一刀声称的机制 | **写完即归档，不要求对下一刀还绿** | "探针顶掉 load ⇒ +2 拍重放"、"恰好交付一次"、"不丢地址" |
| **覆盖** | 跨模块交替 | 唯一真需要维护的一类 | 填充在飞 × 同行 store × 写回排水（`tb_dcache` 的 T8b / T13 那种） |

**四条操作规则**：

1. **新刀要不要写 TB，看 claim 的种类**：claim 是**时间行为**就写（重放几拍、恰好一次、不丢、不是两次）；
   claim 是**结构量**就不写（`44 条 → 0 条` 那类综合侧证据已足够）。
2. **机制 TB 用完即归档**：`Makefile.tb` 用 `wildcard tb/*/*.v` 收集 ⇒ 加一个文件自动进 17/17、删掉自动消失。
3. **禁止动作**：**照当前 RTL 的行为去改期望值** —— 那等于把 bug 洗成 expected。确要改，必须附**独立协议论证**。
4. **这条规则不买覆盖**：我们**没有**约束随机激励 ⇒ 总闸仍是官方 `make test` 19/19 + `make perf` 6/6
   且退出值全对；它们的盲区依旧存在。

**历史沉积的处置**：`tb_dcache` 的 T1~T16 属机制类 ⇒ **留档、允许留红、不进验收**
（它们在 cutX 上就 9 红、刀 AA 后 10 红，红的是"它们测的机制被后来的刀改掉了"，不是设计坏了，
原始取证见 §3.43）。**唯一还开着的口子**见 §1.4。

## 3. 探索过程简要记录

> **压缩说明（2026-10-17）**：§3.1–§3.52 只保留"结果 + 一句机制 + 判据兑现/证伪 + git 指针"；
> 逐级取证、预注册原文与工具读数**查 git 原文**（见 §0 历史检索）。被证伪的读法在对应行内划线留痕。

**口径**：

- **实测** = 官方 `make perf`（`LATENCY=10`、`MAX_CYCLES=100000000`，六例几何平均）或官方 `make test` 门禁
  ⇒ 两者都**必须带 `CONFIG=config.local.mk`**。波形口径的周期起点与 `make perf` 差 16 拍
  （自校验见 `tools/README.md`）。
- **综合** = 官方 `make synth`（新尺），一律走远端 `tools/remote_synth.py pc <id>`，产物用 `tools/snap.py`
  归档进 `docs/timing/results.csv`。**远端不通就停下报告，不经批准不得启用本机容器退路。**
- **模型** = `docs/area_budget.md` §3（历来**高估** 2.6~9.5%）—— 只能用于**排序**，档位判定必须用综合数。
- **上界** = 假设"桶被 100% 抹掉、且转移 1:1"，只用于给候选排序，**不是预测**。

**方法论纪律**（合并去重后）：

1. **转移函数 1:1**：只允许事件式估计 `Δcyc = Σ(实测事件数 × 实测每次省拍)`，两个因子都必须实测。
2. **预注册**：方向性预测写在实验之前；证伪的**划线留痕、不事后改写**。
3. **探针不进 `verilog/`**：OJ 的 stdout 比对是精确全等，一行探针就能把"通过"变成"算错值"。归因计数器只加在 `tools/`。
4. **一次实验只动一个变量**，且每个变体自带 6/6 退出值比对。
5. **改归因工具先标定取位口径**：索引类信号与位段信号混用会静默量错条目；
   锥/扇出类工具每次改动后先拿一根已知答案的网或全局量对账。
6. **扫 VCD 的脚本必须先断言"想要的信号全都在"**（缺一个就 `sys.exit`，不许只 print 警告）；
   按条目切字段的宽度必须**从 `$var` 声明推**并断言整除（写死位宽曾把真值 1321 拍读成 63 拍，差 50 倍）。
   Verilator 的 VCD **没有 `$dumpvars`**，要认 `$enddefinitions`。
7. **本地 TB 的效力边界**：`tb/` 的参数是各自复制的副本 ⇒ 单元 TB 不构成新参数点的正确性证据，
   只是"没误伤"的回归（正确性由官方 `make test` 负责）。
8. **一阶段一提交**；RTL 改动前先汇报、取得批准。
9. **回滚要连带清理引用方**（RTL/tb/docs/tools 全仓按名字 grep）；且 `make -f Makefile.tb run`
   **无视 `TB=` 参数、一律把 `filelist.tb.f` 里所有 VVP 编一遍** ⇒ 一个过期用例能让整条 TB 路编不过。
10. **iverilog 的 generate 作用域不做前向绑定**：声明必须在使用点之前；tb 路（iverilog）与综合路（Yosys）
    的语法容忍度不同，改了 `verilog/` 就两条路都要过。
11. **归因读数的自检**：分类里"最大那一栏机理上讲不通"就是信号（自相矛盾 = 工具错，先怀疑工具）。

## 4. 跨阶段经验

### 4.1 优化判据：什么动作有效（实测总结；2026-10-13 后不再更新）

官方 ABC 是**全局重分解**：动任一处 ⇒ 整片云重新求解 ⇒ 深度重新分配。所以"某条路径变短"不算赢，
**只有结构量变了才算**。

**重解噪声的量级**：cutH↔cutI 两刀的头名是**同一条 RTL 链**（级清单逐段同源），cutI 刀**没碰头名**，
官方周期却从 5.4268 → **5.1357 ns（+5.68%）** ⇒ **±5% 是"什么都没动到头名"时的官方摆动**。
推论：**单刀官方收益 ≲5% 时不得记为机制成立的证据**；判机制只能看结构量（级清单上被削的是第几级、几 ns）。
反向也成立：官方数"没涨"也不等于刀白做；只有结构量停滞才是真失败。

**★ 王冠交接（比噪声更硬，三种形态）**：
① **并列头名**：cutS 的两族近乎并列（div 4.5731 / dcache 4.5588，差 0.3%）；刀 T 削掉 div 族 ⇒
   dcache 族被重解抬到 5.0135，官方周期 4.5732 → 5.1143（**+11.8%**，频率 −10.6%）。
② **支配锥的多分支**：cutV 两族都削掉，头名交给同一条锥的第三个分支（`rs.v`）⇒ 官方只回到 4.8682
（比 cutS 还差 6.5%）。**逐分支切 = 逐次交接**。
③ **同一族的自己**：cutAA 把环削到 0 条，同族其余 544 条被整体抬高 +0.756 ns（+19.6%）⇒ 官方 **−12.16%**。
⇒ 选刀前必须问："**切完头名交给谁？**" 若落点比现在的头名还高（或同族会被吹肥），**这一刀不该切**。
**冗余入口是两笔独立的税，可相加**（cutAA 实测加性：预测 4.5821 vs 4.6094）⇒ 预注册**不许**写"两笔税
会不会相加"这类机理判读，只写**结构判据**（0 条 / 非 0 条）。

**★ 三条常驻结构事实**：
① **支配锥**：一条支配性锥（`sel_all_q`/`sel_valid_q_r` → rs/rob/rat/free_list/ready_table/fetch/icache
的写口），三棵树的全设计最高点都出自它；判**类 1 无对象可删**（真广播）。
② **常驻雷区**：≥128 脚的网三棵树 51/45/56 条、榜首网是三树同一条（596 脚）⇒ 重解**不改变雷区，
只决定哪条路径穿过它、穿几条**。
③ **慢尾肥度 = 比 max 更硬的"刀价值"量**：>4.4 ns 条数 cutR **5** / cutS 88 / cutV **689**（max 4.4154/4.5731/4.8674）；
cutX **0** → cutAA **111**（>4.0 条数 8 → 631），官方同步 −12.16% ⇒ 它**在官方数落定之前就能预告结果**。

**全部动作分三类**：

**类 1 · 删结构 —— 4/6 全对，单刀收益最大；两个反例机理相同。**
判据：官方重综合后**组合面积实测下降**（强信号，非必要条件）。
有效的例子：删 1408 flop D-cache tag 镜像（周期 ×2.32）、SQ 合并链去 4 份字节道复制、SQ 槽索引整片 one-hot、
SQ 合并链改"逐条目贡献 + 年龄 max 归约"。
两个反例：cutU（删 RMW 重复读）与刀 O（288 位载荷 mux 选通）—— 删掉的**不是纯逻辑，而是某条宽网的浅驱动器 /
时序边界**。⇒ **类 1 只在"删掉的东西没有别的作用"时成立** —— 动手前问"这个信号是不是还当着某条宽网的浅驱动器"。
组合面积掉 0.3% 这种量级**不算兑现**（噪声内）。

**类 2 · 在关键路径上真插一级 —— 3/10，唯一能大幅提频的动作；但"切断成功" ≠ "官方变快"。**
判据（事前可查，纯结构量）：把头名路径**逐级打印**，确认要寄存的那组信号**落在这条路径上**。
- 成立：刀 A / 刀 D / 刀 R。刀 R 成立的原因最可复用：它切在**两条共同头名汇合之后的公共段**上。
- 失败：刀 8（没落在头名路径上）、S/T/V（逐分支交接）、W/X/AA（环有冗余入口 / 同族自吹肥）。
- ⇒ 选刀时优先找**汇合点之后**的公共段；找不到公共段（头名族有很多平行入口）时，类 2 大概率是白付 IPC。
- "切完落到第二档"**不能当上界**：第二档随重解动（刀 R 打穿了预注册天花板；刀 S 的新头名比切前还高）。

**类 3 · 只改写法 / 只动扇出 / 给旁路输入打拍 —— 6/6 全负**（+16.2% / +8.24% / +0.49% / +3.25% / +5.76% / +1.97%）。
- 最干净的反例 cutE：寄存的 `fill_wr_w` 只是 `sram_we_w` 的**旁路输入** ⇒ 那颗网与它挂的 36 个脚一个没动，
  尾巴省的 0.91 ns 被 ABC 改走别的分支原样归还。
- 物理原因：ABC 的总账（与 ABC 无关的结构量）全网 Σ 负载脚 299345 → 301625（+0.8%）、
  ≥64 扇出网 335 → 334 ⇒ **负载换了位置、没被删掉**。

**选刀证据只能是级清单。** 反锥成员只说明"能影响终点"，不说明关键路径穿过它
（实测头名反锥 = 4030 门 / 2283 个叶触发器，任何信号都能在某个 4000 门云团里找到影子）。
路径级证据只有一种 = `tools/pathsrc.py <opt> --path N` 的**逐级清单**（时间/增量/脚数/src），
必须点名"削的是**第几级、几 ns**"。`netattr.py` 的锥直方图只配当**辅助**，永不单独当准入依据。

**下刀前必过**：

1. 改前头名的 `pathsrc --path 1` 级清单（点名要削第几级、几 ns，并核对它**在级列表里**——不是"在反锥里"）；
   确认动作落在路径上（类 2）或组合面积真降（类 1）。
2. 记下**头名 − 第二档** = 可赚的空隙（只是量级参考，第二档随重解动）。
