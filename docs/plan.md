**一句话**：功能全通（官方 19/19）、面积在档 3 内；**两个缺口** —— 频率（硬前提 300 MHz，最后实测

## 2. 下阶段任务计划

### 方针（2026-10-01 用户裁定，优先于本文件其余取舍）

> **核心思路 = 提升 IPC 最小的那些程序**；针对"该程序的算法结构 + 它的气泡现状"做定向优化。

判分是 6 个 `perf_*` 的几何平均 ⇒ 相对增益上六程序等价，理由不是权重而是**绝对余量**：
当前 `qsort 0.6071 / towers 0.6752 / median 0.6754` 三个挤在 0.6~0.68，而 `multiply 0.8554 / vvadd 0.8885`
已贴着各自的算法上界 —— 同样一次改动，落在前者身上的绝对空间大得多。

**四个步骤，顺序不可颠倒**（对"扫参数找上限"的正面替代）：

1. 读 `testcases/perf_*/program.S` 定出算法结构：并发地址流条数、复用距离、store:load 比 σ；
2. 用探针定出该程序的气泡归因 —— 到底谁在阻塞（访存延迟 / AR 带宽 / 失效 churn / 前端 / 依赖链）；
3. 用**由算法推出的判据**选方向（`h/m > L`、`a ≈ DC_WAYS/σ`、地址别名关系），而不是试参数；
4. 预注册方向性预测再测；增益落点必须与机制预测逐例对上（对不上就是机制没搞对）。

**逐程序画像**（步骤 1 的产出；结构性量，与参数无关）：IPC 现状见 §1。

| 程序 | 算法 | 并发流 | σ = store/load | `a`（访问/填充） | `a/L` | 结构性气泡 |
|---|---|---|---|---|---|---|
| towers | 链表汉诺塔（`list_push/pop`），足迹 ~360 B ≈ 12 行 | 节点链 + 栈 | **0.84** | 2.48 | **0.31** | 失效 churn（`clr/vset = 9.3×`）；对容量/相联度免疫 |
| qsort | Hoare 划分 + 插入排序叶子（`n≤10`） | 划分双指针 + 校验双流 | 0.37 | 2.72 | **0.34** | 划分循环 load:store = 1:1 且写回刚读的地址；校验双流差 0x2000 同组 |
| rsort | LSD 基数排序，1 KB 计数表 × 32 组恰好 1 行/组 | 计数表 + input + scratch + 校验双流 | 0.76 | 1.90 | **0.24** | 失效 churn（18.5×）；RR 交替驱逐热计数表 |
| median | 顺序扫描 | 1~2 | 0.20 | 13.26 | 1.66 | 已过 `h/m > L` 线，余量小 |
| multiply | 乘加循环，每 81 拍才 1 条 load | 1 | 0.14 | 7.54 | 0.94 | 不是访存程序，缓存对它天然无用 |
| vvadd | 纯顺序向量加 | 3 | 0.25 | 7.89 | 0.99 | 带宽打平，收益全在延迟 |

**反面清单**：不为抬高几何平均去做**只对健康程序有效**的改动；不做**与算法结构对不上**的通用调参。

### 任务（按"硬前提 → 性价比"排序）

#### T1 综合复核本基准 `dc2k_sq8`
- **做什么**：容器 `make synth`（官方 `config.mk` 全默认），量实测面积与 fmax。
- **为什么**：M5 与 S1 两次改动之后**一个综合数都没有** —— 连"是否 ≤12000"都还不知道；面积模型是当前唯一的门。
- **判据**：面积 ≤12000 µm² **且** fmax ≥ 275.86 MHz 噪声带；顺带复核 M5 的 `<200 µm²` 结构估与"探测查表未落在关键路径"。
- **代价**：一次综合；门禁照旧 19/19。

#### T2 综合 `dc2k_c3`（第二个基准候选）
- **做什么**：同一棵树上把 `DC_SIZE` 与 `ROB/RS/BHT/RAS` 调成 `dc2k_c3` 再综合一次。
- **判据**：实测 ≤12000 **且** fmax 不退 ⇒ 换基准（IPC 高 +1.1%）；否则只记录不换。
- **附带**：`ROB 16→32` 的 fmax 代价至今**没有单变量实测**，而频率是硬前提 ⇒ 这次一并量出来。

#### T3 频率：逻辑深度（硬前提）
- **现状**：扇出税已归零（[§15.10.7–33]）⇒ 剩余缺口是**纯逻辑深度**（100 级 vs 需 ≤93 级）。
- **做什么**：路径普查定位关键锥（工具在 `tools/`），单变量削减；每次改动单独综合复核 fmax。
- **判据**：fmax 单调上升，且官方 `make perf` 六例周期数**逐位不变**（有代价必须明示）。

#### T4 双发射在新基线上的复跑（等 T1/T2 的实测面积）
- **已实测的候选**：双发射 `ISSUE_WIDTH=2`（旧基线 +7.50%）与 `w2_stack`（旧基线 **0.7712**，+20.04%）——
  后者是唯一实测能站上 0.75 的底座；两者的数都是**旧 `c2` 基线**。
- **做什么**：在 `dc2k_sq8` 上零 RTL 复跑双发射/`w2_stack`，再按"每 µm² 买多少 IPC"与 T1/T2 的实测面积一起排序。
- **前置**：T1~T3 —— 频率不达标时 IPC 收益不兑现。

## 3. 探索过程简要记录

数字口径：未注明者 = 官方 `make perf`（`LATENCY=10`，六例几何平均）或官方门禁；
**"综合" = 容器 r28 + `-constr`，与官方流程的绝对值不可混用**（见 §4）；模型/估算一律明标。

### 3.1 早期：功能闭环（[§1]–[§12]，2026-09）

- [§1] free_list 重复分配活跃物理寄存器 → 修复（现行设计见 `architecture.md`）。
- [§2] issue/flush 路径的"错路批"泄漏 → 修复。
- [§3] 取指握手重构：标签制 → **地址比对制**（现行契约，见 `architecture.md` 前端一节）。
- [§4] 取指 PC 被陈旧指令的预测劫持 → gcd 死锁；三类陈旧请求统一按**地址不等**丢弃。
- [§5]–[§6] 自建编译/整机链路被官方框架取代；仿真速度根因 = `mul.v` 华莱士树写法（已修）。
- [§7] 18 个编译程序只过 9 个 = 两个独立缺陷（LSQ 窗口语义 + 取指失步）；[§7.4] RS push 被静默丢弃。
- [§8] `lat=20` 口径**已作废**（评测只有 10 拍一个口径）；它逼出的三条修复是现行设计的基础。
- [§9]–[§11] 自建 crt0/链接脚本/ELF→data 全部作废（官方直接给 `program.data`）；Verilator 链路（`make bench`）
  保留，是 sweep 流的基础；Spike 参考方案被首次实测推翻。
- [§12] IPC 第一轮勘察：面积单价校准（已并入 `area_budget.md`）。

### 3.2 官方框架接入与 AXI 闭环（[§13]–[§14]，2026-09-24）

- [§13] 目录迁官方布局（`rtl/`→`verilog/`）；官方 testcases 收敛；容器综合链路（ASAP7 r28 + FakeRAM 面积计入）。
- [§14] `student_top` 包层 + `axi_lite_master` + `mem_subsystem` + MMIO 停机打通；定下 `imem_hit` 门控与
  "提交/完成同拍的 store 不得并入"两条契约。曾判"17 条失败 = 缺 DIV/REM" ⇒ 实测 ≥6 条实为**物理寄存器泄漏死锁**。

### 3.3 除法与频率攻坚（[§15.10]–[§15.14]，2026-09-27~10-01）

- [§15.10] DIV/DIVU/REM/REMU 落地（radix-2 恢复余数 33 拍，不在关键路径上）；官方 19/19（`MAX_CYCLES` 需抬到 1e8）；
  IPC 与基线逐位相同。LB/LBU/LH/LHU 本来就没有缺过（陈旧记录）。
- [§15.10.7–33] **频率攻坚**：扇出税是本设计提频的唯一主因，且属**流程问题不是 RTL 问题** —— 同一份 RTL 加
  `-constr` 后 12.14 → 4.02 ns；普查 8758 个终点、4028 条失败路径只归 **2 个锥**（3966 个吊在同一个 LSQ
  触发器上）⇒ 单点切口、整组受益。曾判"官方流程没有扇出旋钮 ⇒ 提频只能改 RTL"、"病根是深度不是扇出"
  ⇒ 均被实测推翻。
- [§15.11–15.13] 三次负结果：load 往返切半（+3.1% 频率）换来 **−6.07% IPC** ⇒ 回滚（留下定价"往返环上每加
  一个寄存器约值 3.1% IPC"）；容量轴全线 −2.7% ⇒ **划掉**。
- [§15.14] `ROLLBACK_WIDTH` 与 `ISSUE_WIDTH` 解耦（+3.14%；增量严格递减，W=4 已吃到 W=8 的 91%）。

### 3.4 D-cache（[§15.15]–[§二十]，2026-10-01~02）

- [§15.15] 落地：`idxinv` 写策略 + 单 MSHR 合并 + 三路 AR 仲裁 + 污染填充中止（后者 +3.48%）。AR 收支判据
  `h/m > L(=8)` 实测只有 0.46~0.68 ⇒ **净赢靠延迟掩盖而非带宽**；行宽取 32 B（64 B 对 vvadd 物理不可行）。
- [§16 / §十六] 容量轴没牙、相联度轴几乎免费：2 K→8 K ×4 = +0.35%（估算 +2321.9 µm²）；2 K 1→2 路 = **+2.18%**
  （+12.5 µm²）⇒ `DC_WAYS=2` 落地。qsort/rsort 是**冲突缺失**不是容量缺失。
- [§17 / §十七] RR→LRU 被证伪（六例逐位相同）⇒ 反推出相联度买的是"失效间隔内能留住的行数"，不是替换策略质量。
- [§18 / §十八] 写直达 + 命中就地更新（**+20.4%**）：删 `clr_valid`、加 store 口与三态互斥应答；towers +87.9%。
  离线模型预估 +7.8% ⇒ 实测 2.6 倍（模型只用于选型，不做量级预测）。
- [§19 / §十九] 写回 + 脏位（累计 +8.6%）：首发退步 −6.3%，三指针修复后回正；"填充自杀环"修复让 rsort 周期 −37.6%。
- [§20 / §二十] LRU 重测（兑现 [§17] 的欠账）：rsort IPC 0.7229 → 0.7647，geo 0.5942 → 0.6513（+9.6%）；
  四个计数器与离线模型逐项吻合 ⇒ 离线模型第一次成为**经校验的预测器**。

### 3.5 参数前沿与基准切换（[§21]–[§27]，2026-10-02）

- [§21] 修两处"只在 `WR_DEPTH < DC_LINE_WORDS(8)` 现形"的写回 D-cache 静默算错（对已驻留行重复填充 ⇒
  安装时静默作废另一路脏副本）；出货配置 IPC 逐位不变。综合单变量对照：D-cache = **+3288 µm²（+25%）、
  fmax −31.1%、IPC +51.8%**；曾估 +560 ⇒ 实测**低估 5.9 倍**（面积模型按此校准）。
- [§22] 小参数一维消融 24 点（零 RTL）：最大单轴 = `ISSUE_WIDTH=2`（+7.65%/+9.18%）；单轴增长全线**稀释**，
  但增长轴捆起来**超加**（`c3` +5.44% > 三轴之和 +3.5%）；收缩轴严格可加；前沿斜率全部低于基准率 ⇒
  面积换 IPC 在小参数附近关闭。预注册 19 条 11 中 / 8 破。
- [§23] 6 点真面积/真频率综合：fmax 与参数几乎无关（158~166 MHz，极差 ±2.4%，面积跨 1.66×），瓶颈是
  D-cache SRAM 地址路径（72 个宏，广播吃掉 71%）；档 1 不可达（外推到 9000 µm² 得 IPC 0.574 < 0.6000）；
  档 2 缺口在 IPC 不在面积。
- [§24] hanoi 静默算错根因 = **LSQ ↔ 存储一拍竞态**（store 提交与 load 完成同拍，两条路同时丢该 store，
  窗口恰 1 拍）；修法 = 提交失效**延迟一拍**送 LSQ。用自写 RV32IM ISS 作第三方黄金参考逐位相符；
  本地 TB（比官方更严）抓到的真缺陷。
- [§25] IPC 瓶颈归因 = 取指"**1 拍重定向**"气泡（`pc_r` 是"本拍请求的批地址"，而预测跳转晚一拍才解码出
  ⇒ T+1 无批可取）；上限 +13.2%。双发射"只买到 +1.15%"系跨配置比较 ⇒ 同配置实为 **+9.2%**；
  BHT 容量证伪（256/1024 均 0.6511）⇒ 误预测是**数据相关**不是表冲突。
- [§26] D-cache 写粒度 8→32：fmax **165.03 → 240.43 MHz（+45.7%）**、面积 +110.68（+0.68%）、IPC 代价**逐位为 0**。
  曾判"面积不变" ⇒ 证伪（方向仍成立，+0.68% 面积换 1.46× 频率）。
- [§27] 基准切到效率拐点 `c2`（用户裁定，判据是性价比不是档位线）：9783.0 µm² / 166.18 MHz（综合）；
  IPC 起点 0.6513 → 0.5928（−9.0%）。`c2b` 综合 = **9860.864 µm² / 275.86 MHz / 100 级**，离 300 MHz 差 1.09×。

### 3.6 取指、内存墙与三次干预（[§28]–[§34]，2026-10-02）

- [§28] RAS 双缺陷：`is_call` 不认 `auipc+jalr`（六个 perf 程序的调用全是这种）⇒ RAS 恒空；误预测恢复用了
  错的 head ⇒ 撤销了自己刚做的 push。两处同修 +0.39%；`RAS_SIZE` 深度扫描证伪（4→16 只 +0.08%）。
- [§29] **取指同拍推进**（契约改动：`imem_addr` ≡ `exp_pc_r` 的下一个值）：geo 0.5945 → **0.6425（+8.1%）**；

## 4. 口径与纪律

**数字口径**（不标口径的数字不许进本文件）：

- **模型** = `docs/area_budget.md` §3（6 点实测校准，历来**高估** 2.6~9.5%）—— 模型数只能用于**排序**，
  落地与档位判定必须用综合数。
- **上界** = 假设"桶被 100% 抹掉、且转移 1:1"，只用于给候选排序，**不是预测**。

**方法论纪律**：

1. **转移函数 1:1**：只允许事件式估计 `Δcyc = Σ(实测事件数 × 实测每次省拍)`，两个因子都必须实测
   （[§34] 立规，[§37] 首次验证）。
2. **预注册**：方向性预测写在实验之前；证伪的**划线留痕、不事后改写**（[§35]/[§37] 是范例）。
3. **探针不进 `verilog/`**：OJ 的 stdout 比对是精确全等，一行探针就能把"通过"变成"算错值"（[§15.15] 实栽过）。
   归因计数器只加在 `tools/`。
4. **改归因工具先标定取位口径**：索引类信号与位段信号混用会静默量错条目（[§38.3a]）。
5. **一次实验只动一个变量**，且每个变体自带 6/6 退出值比对（`tools/sweep.sh` 内建）。
6. **本地 TB 的效力边界**：`tb/` 的参数是各自复制的副本 ⇒ 改 `student_top.v` 默认值**不**改变它们 ⇒
   单元 TB 不构成新参数点的正确性证据（那是官方 `make test` 的职责），只是"没误伤"的回归。
7. **一阶段一提交**；RTL 改动前先汇报、取得批准。

#### §38.3a 标定预注册（写于标定**之前**，2026-10-08；承接上文"步骤 3a"）

**对象**：`tools/vcd_bubble.py:266` 的 `(v['lq_cand'] >> lh) & 1`，其中 `lh = v['lq_h']` 是**条目号**，
而 `u_lsq.cand` 是**距离索引**（`lsq.v:134-146`：位 gd ↔ 条目 `(head_r + gd) & (LSQ_SIZE-1)`）⇒ 读错位。

**推导（先写死，实测只做证实/证伪）**：该分支已满足 `!misp && !flushing` ⇒ `flush_mask` 全 0 ⇒
`kill[lh] = flush_mask[lh] | invalidate[lh]` 中只有 `invalidate[lh]` 可置；而 `invalidate` 是"提交后失效"，
本分支的 head load `issued_r=0 && data_ready=0` **不可能已提交** ⇒ `kill[lh]=0`；
又 `valid_r[lh]=is_load_r[lh]=addr_ready_r[lh]=1 && issued_r[lh]=done_r[lh]=0` 都在分支条件里，
`winlen ≥ 1 ⇒ in_win(0)=1`，`store_ok[0] = 1'b1`（`lsq.v:132`） ⇒ **`cand[0] ≡ 1`**。

**★ 原判据无判别力（本节订正，跑之前改）**：批准的计划里写的是"A/B ≥ 95% ⇒ 错位成立"，但由上面的推导

改成直接量**两个不同的位**（下三条同时看，缺一不可）：

| 量 | 定义 | 判据 |
|---|---|---|
| `A1` | P 内 `cand[0] == 1` 的拍数 | `A1 / \|P\|` **≥ 95%** ⇒ 上面的推导成立 |
| `B` | P 内**工具现口径**判成 `lm_stblk` 的拍数（= `cand[lh] == 0`） | `A1 ≥ 0.95 · B` 且 `B > 0`（否则本测无信息） |
| `H` | P 内 `lh != 0` 的拍数（= 读错位的拍数） | `H / \|P\|` **≥ 50%** ⇒ 错位是常态而非边角 |

**结论分支**：三条全满足 ⇒ **错位成立**：§35.4 的机制段（"更老 store 未执行完占 17~19%"）与 §35.5 的

**预注册三条判据的对账**：

| 判据（§5.1 预注册原文） | vvadd | rsort | 判 |
|---|---|---|---|
| `A1 / \|P\|` ≥ 95% | 197/238 = 82.8% | 2073/2814 = 73.7% | **证伪** |

⇒ **预注册的"三条全满足"没有触发**，因此**不能**说错位是"按预注册路径确认的"。

**为什么前两条被证伪（我的推导错在哪）**：我推导 `cand[0] ≡ 1` 时用了"本分支的 head load 不可能已提交"，
但**提交失效晚一拍** ⇒ "刚提交、还没从 LSQ 移走"的条目仍留在分支里，此时 `kill[lh]=1` ⇒ `cand[0]=0` 是**正确行为**。
实测把这个边角量化了：`cand[0]==0` 的拍 **100%** 是这一种（vvadd 41 拍、rsort 741 拍，冲刷 0 拍）。
把退休窗口排除后，`cand[0]==1` 的比例是 **197/197 与 2073/2073 = 100%**。

**错位本身成立（判据 3 + 事后交叉表，明确标注为 post-hoc）**：交叉表 `10` 格里 vvadd 196 拍、rsort 1895 拍
是"头条目**本拍可发**、却被记成 `lm_stblk`（更老 store 未执行）"；`00` 格（vvadd 40、rsort 741）是
"头条目正在退休"，也不是"更老 store 挡"。⇒ **`lm_stblk` 的判定 100% 是错的**
（vvadd 236/236、rsort 2636/2636）；反向漏判只有 vvadd 1 拍。

**工具已订正**：`tools/vcd_bubble.py` 改用 `cand[0]`，新增"退休窗口"桶（`lm_stblk` 保留为结构哨兵，
vvadd 实测为 **0**）；订正后 vvadd 的 `lm_dc` 从 0.5% 回到 43%，与独立量 `等存储 ∩ dc_busy`（同拍 60%）同量级
—— 旧值 0.5% 与任何独立读数都不相容，这本身是错位的旁证。

### 5.5 决策

1. **落地 `dc2k_sq8`**（只改 `verilog/top/student_top.v` 的 parameter 默认值 + 文件头注释）。
2. **门禁**：官方 `make test` **19/19**；`make perf` **6/6**，GEOMEAN = 0.7241（与 §5.2 实测逐位一致）；
   单元 TB **17/17**（Icarus）；`verilog/` 无探针残留。
3. **`dc2k_c3` 转入 T2**（模型超门 6.7%，但模型高估方向固定 ⇒ 用综合定案）。
4. 文档同步：`architecture.md` 参数表、`area_budget.md` §4 补一行"基准参数已变、面积未综合"。

### 5.6 store 侧结构项的实践意义评估（零 RTL）

1. **唯一的实测依据已作废**：store→load 转发的依据是 [§35] 的 `lm_stblk` 行（+2.85%，rsort 5.4% / qsort 4.2% /
   median 3.7%）—— §5.4 已证明它与"缺 SQ 位"是两回事，而它自己 **100% 是错位读出来的**（订正后 vvadd 为 0）。
2. **剩下的 store 侧项**是"缺 SQ 位"（上界 +3.07%，rsort 10.1% / towers 7.0%）—— 它是**提交侧**分区的计数器，
   与 `cand` 取位无关，**未受本次订正影响**；而它已经有实测干预：`SQ_DEPTH`/`WR_DEPTH` 4→8（本轮实测
   **+1.20%**，已含在落地基准里）。
3. **剩下没被覆盖的场景**是"更年轻的 load 被更老 store 挡住" —— 本分区看不见，且**没有任何实测值**。
4. ⇒ **结论：无实践意义**（不投入 RTL）。store→load 转发 / 按地址过滤 ticket 的唯一实测依据随 [§38.3a] 作废；
   风险面（字节合并序 + 年龄判定 + "命中在头"语义）按 [§35] 自评高于预取。

## 6. S2 访存并发度 + D-cache 组占用（[§39]，2026-10-08）

零 RTL：新增 `tools/vcd_mem.py`（用法与口径见 `tools/README.md` §1），在**现行基准** `dc2k_sq8` 的
官方二进制波形上跑六程序。目的 = 判定当时仍在候选集里的两个结构项："多 MSHR / 并行填充"与"4 路 + 真 LRU"。

### 6.1 预注册原文（写于测量之前）

- **P1** 六程序 `ld_occ_w` 时间均值 **< 1.3**，且 `≥2` 的拍占比 **< 15%**。
- **P2** 顺序流（vvadd/median/multiply）的 `≥2` 占比**高于** qsort/rsort。
- **P3（判别性）** `fill_pend_w` 事件数 / 需求缺失推送数 **< 20%** ⇒ 硬件串行化**不是**并发度的限制因素
  ⇒ 删"多 MSHR"；**> 50%** ⇒ 串行化成立 ⇒ 多 MSHR 是下一个大件。
- **P4（必须恒成立）** 逐拍 `ld_occ_w == ld_wr_p - ld_rd_p + dc_ms_fire_w`；不成立 ⇒ 口径错、整轮作废。
- **P5** qsort/rsort 的组满（两路全有效）时间占比 **< 15%**（旧写直达口径实测 3.6% / 2.9%）。
- **P6** install 事件里受害路有效（真冲突驱逐）的比例 qsort/rsort **< 25%**。
- 判据：**P5 成立 ⇒ 删"4 路 + 真 LRU"；P5 破 ⇒ 该候选重新进候选集。**

### 6.3 对账（逐条 成立 / 证伪）

- **P4 成立** —— 六程序逐拍 0 拍不符 ⇒ 取位与口径无误，数据可用。
- **P1 成立**（远超阈值）—— 均值 0.003~0.052（阈 1.3），`≥2` 最多 0.29%（阈 15%）。
- **P2 证伪** —— ~~预测顺序流并发更高~~：比率上 qsort 0.29% ≥ vvadd 0.28% > multiply 0.18% > towers 0.14%
  > rsort 0.05% > median 0，方向不成立；**绝对量完全反过来**（qsort 668 / rsort 987 笔 vs 顺序流 2~7 笔）。
- **P3 成立（改用同义的拍数口径）** —— 比率在退化样本上失去分辨力（vvadd 1/2、multiply 5/7 都 >50%，
  但那是 1~5 次事件）；1 格排队被占的拍数最大是 qsort **1352 拍 = run 的 0.59%**
  ⇒ 多 MSHR 的上界 **0.6%** ⇒ 按判据的实质**删"多 MSHR / 并行填充"**。
- **P5 证伪（大破）** —— ~~预测 <15%~~：实测 qsort **31.47/32 = 98%**、rsort 30.26/32 = 95% 的组两路全满。
- **P6 证伪** —— ~~预测 <25%~~：install 时受害路有效 qsort **59%**、rsort **96%**（真冲突驱逐；其中
  23% / 34% 还脏，需写回）。
- **连带作废**：旧口径"组满 3.6% / 2.9%"是**写直达时代**（`idxinv` + 无写分配）的数，[§18]/[§19] 之后
  从未复测。

### 6.4 结论

1. **"多 MSHR / 并行填充"删除**（P3）：需求缺失本身已稀到 qsort 668 笔 / 230k 拍、其余四例 2~7 笔
   ⇒ 并发度不是矛盾 —— **访存缺失这条轴在 M5 之后基本关掉**（真缺失回包只占 run 0.3~4.8%）。
2. **"4 路 + 真 LRU"按判据回到候选集**（P5/P6 破）—— 但它自己的量级上界已经很低：容量 ×4 实测仅 +0.35%
   （[§16]），而 4 路要 4 倍行存；结论是"矛盾不在路数够不够选，在**取进来的东西有没有用**"，
   后者已由 [§40] 关闭（预取零浪费、命中 1 拍）⇒ 该项随本轮一起收口。
3. **预取是 install 的主要来源**（qsort 60%、rsort 63%、vvadd 98%、median 99%），而 qsort/rsort 的
   install 有 59% / 96% 在驱逐**有效行**（rsort 34% 还脏）⇒ 预取在吃掉几乎全部缓存容量；[§35] 的离线
   覆盖率说 rsort 的预取只有 21~38% 命中 ⇒ **预取选择性 / 污染**是最便宜的下一个候选
   （**该候选经 §7 实测证伪删除**：预取行的零消费率只有 0~5%，不是 21~38% 那个口径暗示的"取来没用"）。
4. **[§35] `lm_flight` 的含义订正**（§3.7 已划线）：该桶占 `等存储` 的 33~86%，但段均 **1.4~1.7 拍**、
   **94~95% 的段以"命中/旁路"结束**（只有 2~5% 以自己的 AR 回包结束）⇒ 它是**命中路径的
   load-to-use 延迟**（含 M2 的填充旁路），不是"等自己那笔需求缺失的 14 拍回包"。
   交叉校准：`tools/vcd_mem.py` 复算的 `lm_flight` 与 `vcd_bubble.py` 逐程序差 +0/+2/+4/+15 拍
   （差 = 后者把 `commit` / `flush` 拍先行分类、不计入该桶）。

不计入 V2 结论。另：`vcd_branch.py` 里"PC 多数派"原先标成"上界"，实测被 gshare-10 超过
（median 388 < 446）⇒ 改标为"**无历史**预测器上界"，并**事后加测**(pc,ghr) 上界补上家族天花板（判据不变）。
原"1.4~1.7 拍"（[§39] 的段均值）是**混入了等 AXI 回包的长段**（2% 但长达 21 拍）的均值，非命中路径长度。

### 7.4 结论

1. **预取过滤/降级候选删除**（P7 证伪大破）：预取行零消费率 0~5%，跨六个程序都近乎零浪费 ——
   预取器没有可滤的污染，`DC_PREFETCH=2` 保持。
2. **"换预测器算法"候选删除**（P11 证伪大破）：可实现的 gshare-10 聚合 ≈ **+0.1%**（按实测冲刷代价
   2.0~3.4 拍/次折算，qsort 单程序 −2.4%）；即使给**不可达**的 (pc,ghr) 上界也只 **+2.1% geo**。
   qsort（占总周期 41%）的误预测是**真数据相关**（17 个 PC、33~62% 误预测率），其历史上界比现役更差
   ⇒ 那 10.2% 冲刷是**硬地板**，不是预测器问题。JALR 目标错（towers 80 / multiply 101）折算上界 ≈+0.7%，
   属 RAS 领域，量级不足，记事实不升格。
3. **命中交付路径**：干净命中就是 **1 拍**（P12 的中位/p90 成立），无"长流水"可压 —— 用户 2026-10-08 裁定
   "V3 若降频率则不做"，而实测表明**没有需要改的东西**，故 V3 不产生 RTL 改动。唯一实测到的真损失是
   **SRAM 读口被写口偷 → 查表重放 → head load 多挡 1~2 拍**（towers 4.7% run / qsort 1.8% / rsort 1.2%），
   全部消除的上界 ≈ **+1.3% geo**；任何实现（预读一拍 / 双读口 / 写口让路）都要动 dcache 仲裁。
   用户 2026-10-08 的裁定"V3 若降频率则不做"覆盖此项（三种实现都要动 dcache 仲裁 = 关键路径改动）
   ⇒ 连同它，**本轮 IPC 优化结束**。
4. **单发射的结构探索至此收口**：参数轴（[§38]）、访存缺失/并发（[§39]）、预取过滤 / 预测器算法 /
   命中路径（[§40]）四条全部实测关闭，剩余可干预量都 ≤+1.3% 且要动仲裁或 fmax。下一步转 §2 的
   T1/T2（面积 + 频率实测，硬前提）。
