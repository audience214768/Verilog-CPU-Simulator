# 面积预算与实测（ASAP7 7.5-track RVT TT）

> **口径**（官方，`docs/description.md` §评分标准与时间安排）：`make synth`（Yosys + ABC + OpenSTA，
> `CLOCK_PERIOD_NS` 默认 **2.0 ns**）综合到 ASAP7 7.5-track RVT TT，**总面积 = 组合 + 时序 + SRAM 估算**；
> SRAM 由 `sram_fakeram` 参数估算，**计入**总面积（禁止用寄存器组当内存）。
> 三档（面积上限 µm², 最低 IPC）= **(9000, 0.6000) / (18000, 0.8450) / (36000, 1.0985)**，
> 且 **300 MHz 是三档共同前提**。
>
> **本仓库全部数字分两条流程**，不可混用（用户 2026-10-09 裁定：**只跑官方流程**）：
> - **官方流程**（= §2.1，**判分口径**）= `scripts/synth.py` 原样（裸 `abc -D 2000`）；
> - **`-constr` 流程**（= §2.2，**历史台账，停用**）= 额外 `set_driving_cell INVx1_ASAP7_75t_R` +
>   `set_load 5.0` + `buffer; upsize; dnsize; stime`。ABC 拿到负载信息会插 buffer 树 ⇒ 热网被
>   分摊掉，**fmax 虚高 8.7×、面积虚低 17%**。它只在**内部可比**，**不得当判分数字报**。
> 全部实测点台账在 `docs/timing/results.csv`（含 `flow` 列，**报数只挑 `official` 行**），
> 原始产物在 `docs/timing/<tag>/`。

## 1. 库成本事实（可复用的标定）

**触发器**（官方 r28 库，`synth.py` 走 `dfflegalize`）：

| 单元 | 面积 µm² | 说明 |
|---|---:|---|
| `DFFHQNx1_ASAP7_75t_R` | **0.2916** | ASAP7 最小 DFF；**无复位端**，只有 `QN` 输出（Yosys `$_DFF_P_`） |
| `DFFASRHQNx1_ASAP7_75t_R` | **0.37908**（+30.0%） | 唯一带复位的（异步 set/reset） |

- 该库**不存在同步复位触发器**（`$_DFF_PN0_`/`$_DFF_PP0_` 等全部 `unmapped`；`dfflegalize` 只认
  `$_DFFSR_PNN_`/`$_DFF_N_`/`$_DFF_P_`）⇒ **同步复位会被拆成软逻辑**（`D = rst_n ? d : 0`），更贵。
- **RTL 复位风格现状**（已逐模块核对）：**异步** = `rob`(×2)/`rs`/`rat`/`ready_table`/`axi_lite_master`/`mem_subsystem`/`dcache`；
  **同步** = `prf`/`lsq`/`free_list`/`ras`/`bht`/`fetch`。**新增代码优先异步**。
- ⇒ 面积上的可操作方向：把**数据字段**从复位域摘出去（只复位控制/有效位）。

**SRAM**（`sram_fakeram`，来源 `docs/sram.md` + `scripts/fakeram.py`）：

- 面积 ≈ `DEPTH × WIDTH × 0.0419904 µm²`（按写掩码 lane 分别取整后求和）；
  输出延迟 `0.071262 + 1.67155e-5×DEPTH + 1.243254e-3×GRANULARITY` ns。
- **`DEPTH` 是字（条目）数不是字节数**（旧文在此差过 4×）；1 µm² ≈ **23.8 bit**。
- 实测锚点：I-cache `IC_SIZE=1024 B` ⇒ 9216 bit，拆成 `fakeram_asap7_32x32` 9 个 lane，
  `sram_area_um2 = 386.984`，与 `9216 × 0.0419904 = 386.98` **逐位吻合**。
- **单端口 1RW**（一拍只能读或写）、同步 1 周期读延迟、无复位引脚、`DEPTH×WIDTH ≤ 2^24` 位；
  **绝不能加进 `filelist.f`、绝不能自写 stub**（`sram_fakeram*`/`fakeram_asap7_*` 是框架保留名）。

> `c2` 行是**改粒度之前**的 RTL（rev `8f963e7`）；`c2b` 是同一套参数按 §二十六 之后的 RTL 重综合。
> ~~`c2b` 是当前基准：100 级 / 扇出税 0 / 离 300 MHz 差 1.09×~~
> —— **此行作废**（2026-10-09，[§41]）：`-constr` 下 ABC 得到 `set_driving_cell`/`set_load`，
> 会插 buffer 树把扇出吃掉，所以这里的"扇出税 0"是**变体自己造出来的假象**，不是 RTL 的性质。
> 判分流程（§2.1）实测同源 RTL 为 **31.77 MHz / 扇出税 26.7162 ns（85%）** ⇒ 真实缺口 **9.4×** 而非 1.09×。

**三条硬结论**：

1. **频率曾与结构参数几乎无关**：六点 fmax 极差仅 **±2.4%**，而面积跨 1.66×、触发器跨 1.59×。
   每个点的关键路径终点都是同一处 —— `u_mem.u_dc.u_arr.lane_*/addr_in[*]`（D-cache SRAM 地址口）。
   **300 MHz（3.33 ns）还要快 1.8×，参数扫描给不出这 1.8×**。
   根因：D-cache 用 `WRITE_GRANULARITY=8` ⇒ 被拆成 **71 个 `fakeram_asap7_16x8` 宏**，
   `sram_we_w`（扇出 79）与 `addr_in[1]`（扇出 71）**两级吃掉 4.21 ns，占 6.02 ns 周期的 71%**
   （对照：I-cache 用 `_m32` 只有 9 lane；`dcOffC` 的 `hot_ns = 0`）。
   **已修（`plan.md` §二十六）**：粒度 8→32 ⇒ **71→18 宏** ⇒ **165.03 → 240.43 MHz（+45.7%）**，
   代价 **+110.68 µm²（+0.68%）**、IPC 逐位不变（~~"面积不变"~~ 的估算被实测证伪；
   ~~IPC 代价 −0.13%~−0.27%~~ 实测为 0）。**扇出墙拆掉后瓶颈换成逻辑深度**：
   114 级 × 36.1 ps/级 ⇒ 300 MHz 需 **≤92 级**。
2. **D-cache 的净增量 = +3288.007 µm²**（组合 +1936.749 / 时序 +588.040 / SRAM +763.217），
   换 **IPC +51.8%**（0.4292→0.6513）、**fmax −31.1%**。
3. **面积从来不是约束**：最大实测点 D 也只占档 3 上限的 45%。卡住的是频率（硬前提）与 IPC
   （当前基准 `c2` 的 0.5922 到 0.8 目标差 **+35.0%**）。

## 3. 面积模型（由 6 点实测校准，可直接用于排序）

```
Δarea ≈ Δflops × 0.3186            # 时序：六点在 8738~13921 flops 内吻合 ±1.5%
       + Δflops × β                 # 组合：规整结构 0.65 / LSQ·CAM 类 1.5 / D-cache·PRF 类 4.1
       + ΔSRAM_bits × 0.047         # 实测重标定（早先用的 0.0417 偏低 12%）
```

**边际组合单价 β 因结构而异**（实测三段）：ROB/RS/BHT/RAS/SQ/WR 混合段 = **0.649**；
LSQ + I-cache 段 = **1.525**；DC + PRF 段 = **4.09**。
即 **CAM 味越重，每减一个触发器要多带走 1.5~4 个触发器当量的组合逻辑**（年龄矩阵/tag 比较/路选择）。
`ISSUE_WIDTH=2` 的组合/flop 冲到 **0.918（全场最高）** —— **双发射的代价是组合 >> 时序**。

> **已证伪的两处估算（划线留痕，不要再按它们类推）**：
> ① ~~§2 旧"存储 ≈2444 µm²"~~ —— 只计触发器，实测外围逻辑占 ~69%；
> ② ~~D-cache ≈1075（2 路后 ≈1135）~~ —— 实测 **+3288**，**低估 2.9~3.1×**。
>    SRAM 那一行估对了（773.97 vs 实测 763.217），错在"组合 ~100 量级"（实测 +1936.7）：
>    `tag_r` 镜像、WB 捕获/排水、写通道三段仲裁、2 路 tag 比较 + LRU + 三源 AR 仲裁**全在组合里**。
> ⇒ **涉及新仲裁/新比较器的改动，一律不按旧表类推，必须实测。**

## 4. 档位定位与降面积手段

| 档 | 面积上限 | 最低 IPC | 最近实测点 | 判定 |
|---|---:|---:|---|---|
| 1 | 9000 | 0.6000 | `c2`（9783.0, 0.5928） | 面积超 8.7% 且 IPC 低 1.2%；前沿段斜率 2.43e-5 IPC/µm² 只够 5.5e-6 需要的 1/4.4 ⇒ **参数族不接触角点** |
| 2 | 18000 | 0.8450 | D（16278.4, 0.6513） | 面积余 1721.6 µm² **够**，但 IPC 差 **+29.7%**；按**实测最宽汇率**花光余量也只买到 +6.4% ⇒ **缺口在 IPC** |

- **档位倍数关系**：`IPC ×1.3 ↔ 面积 ×2` **只有 2→3 档严格成立**（0.8450×1.3 = 1.0985 ✓，18000×2 = 36000 ✓）；
  1→2 档面积翻倍但 IPC 倍数是 **1.4083**（0.6000×1.3 = 0.78 ≠ 0.8450）⇒ 1→2 档实际**更陡**。
- **`PRF_SIZE > 32` 是硬约束**：`free_list.v` 的 `BASE = 32`（preg 0..31 恒等映射永不复用），
  `FREE_NUM = PRF_SIZE − 32`；精确下限 **63**（`plan.md` §15.10.15 §六 有证明），
  **`PRF_SIZE = 40` 是永久死锁点**（与 `ROB_SIZE` 无关）。⇒ PRF 消融只能向上（64/96/128）。
- 降面积的"提款机"（收缩参数）**已经提完**：基准从全参 16389 换到 `c2b` **9860.9 µm²**（−39.8%），
  IPC 代价 −9.0%（§二十七）。再往下就是前沿段斜率 2.43e-5 的区域，不划算；本轮不再追面积。
- **当前基准（`dc2k_sq8`）已综合**（2026-10-09，官方流程 tag `offH`）：**11554.026 µm² / 31.4746 ns / 31.77 MHz**，
  模型估的 11752.9 µm² 高估 1.7% ⇒ 阶段 1 门 ≤12000 **通过，余 445.97 µm²**。
  ~~`c2b` 9860.864 µm² / 275.86 MHz~~ 是 `-constr` 流程的数，**不是判分口径**（见 §2.2）。
