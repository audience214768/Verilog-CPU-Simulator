# CPU 2026

## 题目描述


两人一组，完成一个支持指定 RV32IM 指令子集的 CPU。

### 指令集

- 指令集：**RV32IM**。
- 以下指令不做要求：
  - `CSR*`、`ECALL`、`EBREAK` 指令
  - `FENCE`、`FENCE.I` 指令
  - `LH`、`LHU`、`LB`、`LBU`。

### 正确性检验

| 阶段 | 要求 | 累计分数 |
| --- | --- | ---: |
| 基础程序 | 通过：向量乘法、向量加法、`0` 到 `100` 的累加 | 75 |
| 仿真程序 | 继续通过 CPU Simulator 中的程序 | 85 |

未通过前一阶段时，不能获得后一阶段的分数。

### 性能与面积（待定）

功能验证通过后进行性能评分。以 [Sodor](https://github.com/ucb-bar/riscv-sodor) 的顺序执行五级流水线 CPU 作为 baseline。

- **面积**：使用 **Yosys + ASAP7** 综合评测。
- **IPC**：使用 Verilator 对 Verilog RTL 进行仿真统计。
- **频率**：你的 CPU 频率需要不低于 **300 MHz**。
- 面积和 IPC 必须同时满足某一行的限制；在频率满足要求的前提下，每通过一个阶段 **+5 pts**，通过更高级的阶段会同时拿到低阶段的分数。

| 阶段 | 最大面积 | 最低 IPC | 累计分数 |
| --- | ---: | ---: | ---: |
| 1 | 10,000 | 0.6000 | 90 |
| 2 | 20,000 | 0.7800 | 95 |
| 3 | 40,000 | 1.0140 | 100 |

档位按“IPC 每增加至 1.3 倍，面积上限增加至 2 倍”设置。

IPC 计算的测试点为 [BenchMark]( https://github.com/ACMClassCourse-2025/CPU-2026-Benchmark).

### 参数化

在最终的设计中，CPU 发射宽度、物理寄存器大小、ROB 大小等理应可被参数化。

### 最终成果

提交 CPU 和两份报告：
  - 性能对于每个参数的敏感度（e.g. 不同发射宽度/不同寄存器组大小/不同 ROB 大小下 ipc 的变化）
  - 过程中对架构设计的探索

### 时间安排

第 14 周周六 23:59 DDL，第 7 周中期检查

### 其他

- 实现语言不限，可使用 **Verilog/SystemVerilog、Chisel、Assasyn** 等。
- Yosys 的评测输入为 Verilog。因此，使用其他 HDL 的同学必须先将设计转换为可供 Yosys 和 Verilator 使用的 Verilog RTL，再进行面积和 IPC 评测。
- 内存不会被 Yosys 综合，其面积**不计入**面积成绩。（除非使用寄存器组作为内存——不，这是不被允许的）
- 指令和数据访问采用**冯·诺依曼结构**：只有一个统一内存（当然，可以自行添加 I-cache 与 D-cache）。
- 内存的读取写入延迟为 3 周期，而如果试图获取性能阶段的分数，要求内存的延迟为 20 周期。
- AI Policy: 不做限制，但是 CR 时会考察设计细节，例如某个模块中的具体 trade-off，以及如果使用 AI 会额外考察与 LLM 的交互方式。
